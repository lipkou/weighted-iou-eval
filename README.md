# weighted-iou-eval

Оценка качества разметки (детекция и сегментация): предсказанная разметка сравнивается с эталонной.
Результат — оценка каждого объекта, каждого класса и всего файла в процентах, плюс precision/recall и совпадение атрибутов.

## Запуск

Windows:

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt

.venv/Scripts/python -m weighted_iou road_data/ground_truth/road.jpg.json road_data/annotated/road.jpg.json
.venv/Scripts/python -m pytest
```

Linux / macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

.venv/bin/python -m weighted_iou road_data/ground_truth/road.jpg.json road_data/annotated/road.jpg.json
.venv/bin/python -m pytest
```

## Метрика

Обозначения: g — объект эталона, p — объект предсказания, A — площадь в пикселях, w(A) — вес объекта (`A` или `√A`, `scoring.object_weight`).

1. **Сопоставление** — без учёта класса, венгерский алгоритм по максимуму суммарного IoU. Пара с IoU < `matching.min_iou` не засчитывается.
2. **Объект:** `s_g = IoU(g, p)`, если g сопоставлен с p и классы совпали, иначе 0.
   Неверный класс — это пропуск в классе эталона и FP в классе предсказания; в отчёте помечается «нашёл, но не тот класс».
3. **Класс c** (классы эталона и предсказания вместе):

   ```
   S_c = Σ w(A_g)·s_g / ( Σ w(A_g) + λ·Σ_{p∈FP_c} w(A_p) )
   ```

   λ = `scoring.fp_penalty`; при λ = 1 ложный объект стоит столько же, сколько пропуск объекта той же площади.
   Класс, где есть только FP, получает 0.
4. **Файл:** `S = Σ W_c·S_c / Σ W_c`, W_c — вес класса из `config.toml`. Пустой кадр с обеих сторон = 100%.
5. **Precision / recall** по классу: TP — совпавший класс и IoU ≥ `tp_iou` класса (по умолчанию `scoring.default_tp_iou`). Порог влияет только на счётные метрики, не на оценку.
6. **Атрибуты** в оценку не входят: выводится доля совпавших значений объектов и расхождения атрибутов кадра (например, погоды).

## Формат данных

JSON — список из двух блоков: `[0]` — метаданные кадра и типы объектов, `[1]` — геометрия; связь по `nm`.
Номера `nm` в эталоне и предсказании независимы. Геометрия берётся из маски `<file>.images/<frame>/<nm>.png`, если она есть, иначе из полигона `path`, иначе из bbox.
Имена классов нормализуются: `road sign` = `road_sign`.

**Растеризация** повторяет правило инструмента разметки: координаты округляются вниз, пиксель входит в фигуру, если его центр внутри; для bbox это `floor(x1) ≤ i < floor(x2)`.
Правило выведено из эталона, где у каждого объекта есть и bbox в JSON, и маска: оно воспроизводит маски bBox попиксельно и все 32 границы bbox 8 объектов
(округление и «центры пикселей без floor» дают 21 из 32). Для полигонов проверены только границы — вершин эталонных полигонов в данных нет.

## Выводы по данным (`road_data`)

Оценка файла **57,7%** (car 79,7%, road_sign 37,4%, road_barrier 46,5%; λ = 1, вес по площади).
Расхождения просмотрены на изображении с наложенными масками:

| Расхождение | Причина | Почему |
|---|---|---|
| Ограждения: IoU 0.43 и 0.51, предсказание почти вдвое больше по площади | **Правила разметки** | Эталон — только планка, предсказание — планка вместе со стойками до земли. Сдвиг тонкой (~8,5 px) планки на 1–2 px дал бы IoU 0.6–0.8, а не 0.4–0.5 |
| Знак GT 0.5 ↔ pred 0.7: IoU 0.40, bbox в 2,4 раза выше | **Правила разметки** | В предсказании знак размечен вместе со столбом |
| Ограждение огибает машину | **Не ошибка** | Обе разметки вырезают перекрывающую машину из ограждения; наложение 26 px в предсказании — неточность контура |
| Пропущена машина GT 0.4 (94 px) | **Модель** | Белая машина вдали видна на снимке (если в правилах есть минимальный размер объекта — может быть правилом) |
| Ложный знак pred 0.5 (436, 388) | **Модель** | Серое пятно в кустах, знака нет |
| `oncoming = true` у GT 0.3 | **Модель** | Машина справа от двойной сплошной, едет в попутном направлении |
| `oncoming = null` у GT 0.1 | **Модель** | Атрибут не заполнен |
| Погода `fog` | **Модель** | На снимке ясно (`clear` в эталоне) |

Самые большие потери оценки (ограждения и крупный знак) дают различия в правилах разметки, а не ошибки модели,
поэтому 57,7% занижают качество модели. Порог TP для ограждений оставлен 0.5: снижение до 0.3 скрыло бы это расхождение в правилах.
Пара ограждений GT 0.7 ↔ pred 0.8 (IoU 0.509) проходит порог с минимальным запасом.
